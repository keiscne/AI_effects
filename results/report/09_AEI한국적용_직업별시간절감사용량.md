# AEI로 한국만을 대상으로 직업별 시간절감률·사용량을 계산할 수 있는가

### --- 어떤 릴리스·파일을 쓸 것인가, 국가 단위 해상도의 실제 한계, 그리고 GLOBAL 시간절감률을 한국에 적용하는 방식의 타당성 검증 ---

**AI-effects 프로젝트**

## 초록

본 노트는 "한국만을 대상으로 Anthropic Economic Index(AEI) 데이터를 이용해 직업별 노동시간 절감률(time savings)과 직업별 AI 사용량을 계산할 수 있는가"라는 질의에 대한 답을 정리한 작업 노트다. `08_AEI데이터_노동시간_사용량_스키마.tex`가 AEI 데이터셋의 필드 구조를 일반적으로 정리했다면, 본 노트는 그 구조를 **한국(`geo_id="KOR"`)이라는 구체적 국가에 실제로 적용했을 때 무엇이 가능하고 무엇이 불가능한지**를 HuggingFace `Anthropic/EconomicIndex` 저장소의 원자료를 직접 다운로드해 검증한다. 핵심 결론은 세 가지다. (1) 완성된 형태로 다운로드 가능한 릴리스는 `release_2026_06_26`(V6) 하나뿐이며, 그 이전 릴리스(V4·V5)는 최종 집계본을 공개하지 않는다. (2) 국가 단위(한국 포함)에서는 직업별 시간절감률이 SOC 대분류(Major Group, 22개) 수준까지만 제공되고, SOC 세부직업(Detailed Occupation, 6자리) 수준의 시간절감률은 국가 단위에는 존재하지 않는다—세부직업 수준 시간절감률은 `GLOBAL` 단위에만 존재한다. (3) 한국의 세부직업별 사용량(424개 O*NET-SOC 코드, 2026년 5월 기준)과 `GLOBAL` 세부직업별 시간절감률(717개 코드)을 결합하면 커버리지 100%로 조인되어, 세부직업 단위 분석이 기술적으로 가능하다—단 이는 "한국 고유의 실현 크기"가 아니라 "한국의 사용 비중 × 전세계(사실상 미국 비중이 큰 표본) 평균 시간절감률"이라는 혼합 지표이므로, 국가 간 시간절감률 동질성이라는 명시적 가정을 전제해야 한다.

## 1. 서론: 질의와 검증 방법

`08_AEI데이터_노동시간_사용량_스키마.tex`는 AEI 데이터셋의 필드 구조를 릴리스 전체에 걸쳐 문서 수준에서 정리했다. 그러나 "한국만을 대상으로" 분석이 가능한지는 문서만으로는 확정할 수 없다—국가 단위 데이터가 실제로 존재하는지, 프라이버시 임계치를 통과하는지는 원자료를 열어봐야 알 수 있다. 본 노트는 다음 두 질의에 답하기 위해 `Anthropic/EconomicIndex` 저장소의 `data_documentation.md`를 릴리스별로 재대조하고, 실제 CSV 원자료(`release_2026_06_26/data/aei_claude_ai_2026-06-26.csv`, 219MB)를 다운로드해 `geo_id="KOR"`·`geo_id="GLOBAL"` 행을 직접 집계했다.

1. 직업별 노동시간 절감률과 직업별 AI 사용량을 한국만을 대상으로 계산하는 것이 가능한가. 가능하다면 어떤 파일·릴리스를 써야 하는가.
2. 직업별 시간절감률은 `geo_id="GLOBAL"`의 값을 한국에도 그대로 적용하고, 직업별 사용량은 `geo_id="KOR"`의 값을 채택하는 하이브리드 방식이 가능한가. 가능하다면 SOC 분류는 몇 자리까지 가능한가.

## 2. 어떤 릴리스·파일을 써야 하는가: 완성 집계본이 공개된 릴리스는 V6뿐

`08_AEI데이터_노동시간_사용량_스키마.tex` 표1은 V4(`release_2026_01_15`)·V5(`release_2026_03_24`)도 "동일 스키마 유지"라고만 기술해, 완성된 집계 CSV가 두 릴리스에도 존재하는 것처럼 읽힐 수 있다. 그러나 HuggingFace API(`tree` 엔드포인트)로 각 릴리스의 `data/` 폴더를 직접 조회한 결과, 실제 공개 파일 구성은 다음과 같다.

**표 1. 릴리스별 실제 공개 파일 (2026년 9월 HuggingFace API `tree` 엔드포인트 직접 조회)**

| 릴리스 | `data/` 폴더 실제 내용 | 완성 집계본 여부 |
|---|---|---|
| `release_2026_01_15` (V4) | `data/intermediate/aei_raw_claude_ai_2025-11-13_to_2025-11-20.csv` (94MB, **1주일치 pre-enrichment 원시본**) | 없음 — raw 스냅샷만 공개 |
| `release_2026_03_24` (V5) | `data/intermediate/aei_raw_claude_ai_2026-02-05_to_2026-02-12.csv` (103MB, **1주일치 pre-enrichment 원시본**) | 없음 — raw 스냅샷만 공개 |
| `release_2026_06_26` (V6) | `data/aei_claude_ai_2026-06-26.csv` (219MB, **2026년 4–5월 2개월치, enrichment 완료된 최종본**) | **있음** |
| `labor_market_impacts` | `job_exposure.csv`(37KB), `task_penetration.csv`(1.9MB) | 있음(단, 지리 컬럼 없음, §5 참조) |

V4·V5의 파일명이 `aei_raw_claude_ai_*`이고 경로가 `data/intermediate/`라는 점 자체가 이 파일들이 프라이버시 임계치 적용 이전의 중간 산출물임을 가리킨다. `data_documentation.md`(V4)도 "AEI 원시 파일은 원시 건수·비율을 담고 있다"고 명시하며, enrichment(지리 코드 3자리 변환, 프라이버시 임계치 적용 등)는 별도 단계로 문서에 기술되어 있을 뿐 그 결과물 파일은 저장소에 공개되어 있지 않다. 반면 V6은 파일명이 `aei_claude_ai_*`(`raw` 접두어 없음)이고 `data/` 최상위에 있어, enrichment가 완료된 배포용 최종본이다.

**따라서 한국 분석에 쓸 파일은 `release_2026_06_26/data/aei_claude_ai_2026-06-26.csv` 하나로 좁혀진다.** V4·V5의 raw 파일을 쓰려면 연구자가 직접 enrichment 로직(지리 코드 매핑, 최소 관측치 임계치 적용 등)을 재구현해야 하며, 이는 재현성·검증 부담이 크므로 권장하지 않는다.

## 3. V6 스키마의 국가 단위 해상도 제약

V6 `data_documentation.md`의 컬럼은 `date_start, date_end, geo_id, geo_level, category_name, hierarchy_level, metric_id, value, node_name, node_external_id`이며, `category_name`은 `overall`(전체)·`onet`(O*NET 과업)·`request`(요청군집)·`soc_occupation`(SOC 직업) 4종이다. 이 중 "Metric Availability" 표가 지리 단위별로 어떤 조합에서 전체 지표(시간 지표 포함)가 제공되는지를 명시한다(문서 원문을 그대로 인용).

**표 2. V6 "Metric Availability" 표 (`release_2026_06_26/data_documentation.md` 원문)**

| Source | Geography | Overall | O\*NET | Request | SOC | 제공 지표 |
|---|---|:---:|:---:|:---:|:---:|---|
| `claude_ai` | Global | ✓ | ✓ | ✓ | ✓ | 전체 지표(시간 지표 포함) |
| `claude_ai` | Country | ✓ | — | — | — | 전체 지표 |
| `claude_ai` | Country | — | ✓ | ✓ | ✓ | `pct`만 |
| `claude_ai` | Country | — | GWA(최상위) | Major(최상위) | Major Group(최상위) | 전체 지표 |
| `claude_ai` | Subregion | ✓ | — | — | — | 전체 지표 |
| `claude_ai` | Subregion | — | ✓ | ✓ | ✓ | `pct`만 |

문서 원문: *"A cell is only published if it meets both the aggregation thresholds and the geography sample floor for the given row."*

즉 **국가(Country) 단위에서는 직업 카테고리(`soc_occupation`)의 최상위(가장 성긴) 계층—Major Group, SOC 2자리 대분류—에서만 시간 지표를 포함한 전체 지표가 제공**되고, 가장 세밀한 계층(Detailed Occupation, SOC 6자리)에서는 `pct`(사용 비중)만 제공된다. 세부직업 단위 시간 지표는 오직 `Global` 행에만 존재한다. 이 표는 `08_AEI데이터_노동시간_사용량_스키마.tex`가 정리한 V3·V4 시점 문서(국가당 최소 200건 대화, 미국 주당 100건이라는 국가 포함 임계치)와는 별개의, **셀 단위 해상도 제약**이다.

## 4. 한국(`geo_id="KOR"`) 실제 데이터 검증

위 문서상 제약이 한국에도 실제로 적용되는지, 그리고 한국이 애초에 국가 포함 임계치를 통과하는지를 219MB 원자료를 직접 다운로드해 확인했다.

**표 3. `geo_id="KOR"` 실측 결과 (2026년 4–5월, `soc_occupation` 카테고리)**

| `hierarchy_level` | 의미 | 확인된 행 수 | 제공 지표 |
|---|---|---|---|
| 0 (Detailed Occupation, SOC 6자리) | 세부직업 | `pct` 813행, 시간 지표 **0행** | `pct`만(문서 예측과 정확히 일치) |
| 1 (Major Group, SOC 2자리) | 대분류(22개) | 전 지표 2,244행(22개 대분류 × 2개월 × 약 51개 지표) | `human_only_time_mean`·`human_with_ai_time_mean` 등 전 지표 |
| (참고) `overall` 카테고리 | 국가 전체 | 다수 | 전 지표 (직업 미분해) |

- 한국은 `geo_id="KOR"`, `geo_level="country"` 전체로 11,601행이 존재해 국가 포함 임계치를 통과한다.
- 대분류(레벨 1) 22개 전부가 관측되며, 모두 `human_only_time_mean`(시간 단위)·`human_with_ai_time_mean`(분 단위) 쌍을 갖는다.

**계산 예시** (2026년 5월, "Computer and Mathematical" 대분류, SOC 코드 15):

$$
\text{human\_only\_time\_mean} = 5.28\text{시간}, \quad \text{human\_with\_ai\_time\_mean} = 42.12\text{분}
$$

$$
\text{시간절감률} = 1 - \frac{42.12 / 60}{5.28} = 1 - 0.133 \approx 86.7\%
$$

이는 `08_AEI데이터_노동시간_사용량_스키마.tex` §2.4가 "문서에 단위 미명시"로 남겨둔 문제를 해소하는 근거이기도 하다—V6 `data_documentation.md`는 `human_only_time_mean`의 단위를 **시간(hours)**, `human_with_ai_time_mean`의 단위를 **분(minutes)**으로 명시적으로 기술한다. Tamkin and McCrory의 원 방법론(전자는 시간 단위, 후자는 분 단위로 프롬프트 설계)이 공식 데이터셋에 그대로 반영되어 있음이 V6 문서로 확인된다.

## 5. GLOBAL 시간절감률 + KOR 사용량 결합: 기술적 검증과 방법론적 한계

### 5.1 기술적 조인 가능성: 실측 결과

`geo_id="KOR"`의 세부직업(레벨 0) 사용 비중과 `geo_id="GLOBAL"`의 세부직업 시간절감률을 O*NET-SOC 코드(`node_external_id`)로 조인할 수 있는지를 실제로 확인했다.

**표 4. GLOBAL–KOR 조인 커버리지 (2026년 5월 기준)**

| 대상 | 코드 수 |
|---|---|
| `geo_id="KOR"`에서 관측된 세부직업 코드(레벨 0, `pct` 존재) | 424개 |
| `geo_id="GLOBAL"`에서 시간 지표가 존재하는 세부직업 코드(레벨 0) | 717개 |
| 한국 424개 코드 중 GLOBAL 시간 지표에 매칭되지 않는 코드 | **0개** |

한국에서 관측되는 세부직업 코드 424개 전부가 GLOBAL 세부직업 시간 지표에 존재해, **커버리지 100%로 조인 가능**하다. 즉 기술적으로는 다음 방식이 가능하다.

$$
\text{한국 직업 }o\text{의 시간절감률} := 1 - \frac{\text{GLOBAL\_human\_with\_ai\_time\_mean}_o / 60}{\text{GLOBAL\_human\_only\_time\_mean}_o}, \qquad \text{가중치} := \text{KOR\_pct}_o
$$

### 5.2 방법론적 한계: 무엇을 가정하는 것인가

이 결합이 기술적으로 가능하다는 것과, 결과가 "한국 고유의 실현 크기"를 나타낸다는 것은 다른 문제다. `08_AEI데이터_노동시간_사용량_스키마.tex` §5.3이 정리한 "이론적 상한 × 실현 여부 × 실현 크기" 구조를 빌리면, 이 방식은 세 번째 항(실현 크기, 시간절감률)을 한국 고유값 대신 **GLOBAL 대리값(proxy)으로 치환**하는 것이다. 다음 세 가지를 방법론 절에 명시적 가정으로 적어야 한다.

1. **국가 간 동질성 가정**: 특정 직업의 AI 사용에 따른 시간절감 정도가 국가와 무관하게 동일하다고 가정한다. 이는 검증되지 않은 가정이며, 대분류(레벨 1) 수준에서는 한국 고유값이 실제로 존재하므로(§4), 이를 GLOBAL 대분류값과 비교하는 민감도 분석으로 가정의 타당성을 부분적으로 점검할 수 있다.
2. **GLOBAL의 실질적 구성**: `GLOBAL`은 전세계 대화의 합산이므로, Claude 사용자 지리 분포상 영어권(특히 미국) 비중이 상당할 가능성이 크다. "GLOBAL을 한국에 적용한다"는 것의 실질적 의미는 "영어권 중심 표본의 직업별 시간절감 패턴을 한국에 적용한다"에 가까울 수 있다.
3. **사용량과 시간절감률의 결합 층위 불일치**: 사용 비중(`pct`)은 한국 고유 관측치이고 시간절감률은 전세계 관측치이므로, 산출되는 지표는 순수한 "관측된 실현 크기"가 아니라 "한국의 실현 여부 × 전세계 평균 실현 강도"라는 혼합 지표임을 논문 본문에서 구분해 표기해야 한다(예: "한국 적용 추정치"와 "한국 고유 관측치"를 별도 계열로 병기).

## 6. SOC 코드는 몇 자리까지 가능한가

`node_external_id`는 O*NET-SOC 2019 확장 코드(예: `11-3071.04`) 형식이다. 앞 6자리(`11-3071`)가 표준 SOC **세부직업(Detailed Occupation) 코드**이며, 소수점 뒤 2자리는 SOC보다 더 세분화된 O\*NET 고유 확장(하나의 SOC 코드가 여러 O\*NET 직업으로 더 쪼개지는 경우에 부여됨)이다. `soc_occupation` 카테고리는 이 중 두 계층만 노출한다—레벨 0(세부직업, 사실상 SOC 6자리)과 레벨 1(대분류, SOC 2자리)이며, 표준 SOC 체계의 중간 계층(3자리 소분류, 5자리 광의직업)은 AEI 데이터에 별도로 존재하지 않는다.

| 구분 | SOC 자릿수 | 국가(KOR) 단위 제공 지표 | GLOBAL 단위 제공 지표 |
|---|---|---|---|
| 레벨 1: Major Group | 2자리 | 전 지표(시간 포함) | 전 지표(시간 포함) |
| 레벨 0: Detailed Occupation | 6자리(O\*NET 확장 시 6자리+2자리) | `pct`만 | 전 지표(시간 포함) |

따라서 §5의 GLOBAL–KOR 결합 방식을 쓰면 **SOC 6자리(세부직업) 수준까지** 분석이 가능해진다. 이 방식을 쓰지 않고 한국 고유값만 쓴다면 **SOC 2자리(대분류, 22개 범주) 수준**으로 제한된다.

## 8. 보론(2026-09-27 추가): V5 원자료 재검토와 V5·V6의 직업 분류 활용 수준 비교

이 절은 2026년 9월 27일에 추가한 것이다. §1–7의 본문은 수정하지 않았다. §2와 §7 표의 V5 관련 판단("pre-enrichment 원시본이라 부적합")은 **이 절의 검증 결과로 정정한다.** 두 서술이 충돌하면 이 절을 따른다.

### 8.1 V5 원자료 직접 검증

로컬에 저장한 V5 파일(`release_2026_03_24/data/aei_raw_claude_ai_2026-02-05_to_2026-02-12.csv`, 2026년 2월 5–12일 1주)을 직접 집계했다.

1. **공개 임계치는 이미 적용되어 있다.** 한국(`geo_id="KR"`) 과업 중 가장 작은 칸이 15건이고, 임계치에 못 미치는 과업은 `not_classified`로 합산되어 있다(한국 대화의 24.9%, GLOBAL 2.7%). 파일명의 `raw`는 O\*NET·SOC 계층이나 인구 자료를 붙이는 enrichment 이전이라는 뜻으로 보이며, 프라이버시 처리 이전 자료라는 뜻은 아닌 것으로 판단된다.
2. **Fan and Nguyen(2026)이 쓴 R5 자료와 같은 파일이다.** 원문 Box 2의 수치와 정확히 일치한다. "modify existing software" 과업 41,586건, 분류된 대화 972,636건(= 100만 − `not_classified` 27,364), AI 없이 3.54시간 → AI 활용 시 17.8분.
3. **스키마가 V6와 다르다.**
   - 건수(`*_count`)가 있다. V6에는 점유율만 있다.
   - `soc_occupation` facet이 없다. 직업 단위로 가려면 과업→직업 연계가 필요하다.
   - 국가 코드가 2자리다(`KR`).
   - 과업별 절감시간(`onet_task::human_only_time` 등)은 GLOBAL에만 있다(3,259개 과업). 한국 행에는 국가 전체 평균만 있다.
4. **과업→직업 연계가 사실상 완전하다.** `release_2025_09_15/data/intermediate/onet_task_statements.csv`(O\*NET 20.1, SOC 2010 코드)와 과업 텍스트를 대소문자 구분 없이 맞추면 다음과 같다.
   - GLOBAL: 3,258개 과업 전부 매칭(`none`, `not_classified` 제외)
   - 한국: 299개 과업 전부 매칭
   - 86개 과업(대화의 4.5%)은 여러 직업에 걸려 있어, 해당 직업에 똑같이 나눈다.
   - 연계 결과 세부직업 수는 GLOBAL 566개, 한국 171개다.

따라서 V5는 **분석에 쓸 수 있는 공개 집계본**이다. 건수와 과업별 95% 신뢰구간이 있어, LCE 재현(Fan and Nguyen의 상한·하한 시나리오 포함)에는 오히려 V6보다 유리하다.

### 8.2 V6 한국 행의 추가 확인

같은 기준으로 V6 한국(`geo_id="KOR"`) 행을 다시 집계했다(2026년 4월 / 5월).

| 항목 | 2026.4 | 2026.5 |
|---|---|---|
| `soc_occupation` 레벨 0(세부직업) 공개 코드 수 | 389 | 424 |
| 세부직업 `pct` 합계 | 96.16% | 98.08% |
| `onet` 레벨 0(과업) `pct` 합계 | 78.51% | 81.32% |
| 세부직업 `pct` 최솟값 | 0.01% | 0.01% |
| 국가 단위 직업별 절감시간 | 대분류 22개만 | 대분류 22개만 |

같은 한국 행인데도 과업 단위 합계(79–81%)가 세부직업 단위 합계(96–98%)보다 훨씬 낮다. 이는 V6가 공개 임계치를 **직업 단위 칸**에 따로 적용하기 때문으로 보인다. 직업은 여러 과업을 모은 단위라 임계치에 걸려 빠지는 몫이 적다. 반면 V5는 과업 단위로만 임계치가 적용되어 있어서, 과업을 직업으로 다시 묶어도 이미 빠진 몫(`not_classified` 24.9%)은 되살릴 수 없다.

V6에는 건수가 없고, 월별 표본 크기도 원자료 문서와 Cadences 보고서(Massenkoff et al. 2026) 어디에도 나오지 않는다. `pct`는 소수 둘째 자리로 반올림되어 있다. 따라서 V6 세부직업 값의 **포괄률은 높지만 정밀도(칸별 오차)는 평가할 수 없다.**

### 8.3 V5·V6 직업 분류 활용 수준 비교

**표 8.1. 용도별 V5·V6 직업 분류 활용 수준**

| 용도 | V5 (2026.2, 1주) | V6 (2026.4–5, 월별) |
|---|---|---|
| **GLOBAL 직업별 절감시간** | 세부직업 가능 (과업 연계로 566개, 대화의 93% 포괄, 건수·신뢰구간 있음) | 세부직업 가능 (자체 제공 717개) |
| **KR 직업별 사용량** | **대분류 권장** (세부 171개로 나눌 수는 있으나 포괄률 70.3%, 과업 299개 중 145개가 30건 미만) | **세부직업도 활용 가능** (389–424개, 포괄률 96–98%). 단 정밀도는 확인할 수 없음 |
| **KR 직업별 절감시간** | 관측 불가 (국가 전체 평균만 있음) | **대분류(22개)만** 직접 관측 |

해석은 다음과 같다.

1. **GLOBAL에서는 두 릴리스 모두 세부직업까지 쓸 수 있다.** V5도 과업→SOC 연계로 세부직업 수준을 충분히 만들 수 있고, 건수와 신뢰구간이 있어 더 투명하다.
2. **한국 사용량은 V6가 세부 분류에 더 적합하다.** 이유는 8.2절의 임계치 적용 단위 차이다.
3. **V6 세부직업 값의 정밀도는 보장되지 않는다.** 세부직업 결과는 순위나 상위 직업 위주로 해석한다. 회귀 등에 쓸 때는 4·5월을 합치거나, SOC 소분류(3자리) 또는 ISCO 2자리로 묶은 버전을 함께 제시한다.
4. **한국 직업별 절감시간은 두 릴리스 모두 세부직업 수준에서 관측되지 않는다.** 세부직업으로 가려면 어느 릴리스든 GLOBAL 과업·직업별 절감시간을 빌려 와야 한다(§5의 결합 방식). 한국 고유 값은 V6 대분류뿐이다.

요약하면 다음과 같다. **한국 사용량은 V5 대분류, V6 세부직업(해석 주의)까지 쓸 수 있다. 절감시간은 GLOBAL에서 두 릴리스 모두 세부직업까지, 한국에서는 V6 대분류까지만 쓸 수 있다.**

### 8.5 §7 실행 권고에 대한 보완

- **파일 선택**: V6 단일 파일이라는 권고를 "V6를 기본으로 하되, V5(`release_2026_03_24`)도 사용 가능"으로 보완한다. 특히 건수가 필요한 분석(LCE 재현, 신뢰구간)에는 V5가 적합하다.
- **V5 do 파일 주석에 명시할 사항**: (1) 국가 코드 `KR`(2자리), (2) 과업→직업 연계표 `release_2025_09_15/data/intermediate/onet_task_statements.csv`(O\*NET 20.1)와 매칭 키(소문자 변환한 과업 텍스트), (3) 다중직업 과업의 균등 배분 규칙, (4) 시간 단위(`onet_task_human_only_time_mean`=시간, `onet_task_human_with_ai_time_mean`=분).
- **V5와 V6의 시계열 비교**: 두 릴리스는 기간 단위(1주 vs 월), 직업 코드 체계(연계로 만든 SOC 2010 vs V6 자체 제공 코드), 임계치 적용 단위가 다르다. 직업별 비중의 변화를 해석할 때 이 차이를 함께 적는다.
- **1P API**: V5 API 표본에는 Claude Code가 포함되어 있고(Massenkoff et al. 2026, Learning Curves p.5), V6 API에서는 제외되어 있다. V5와 V6의 API 직업 구성은 직접 비교하지 않는다.
